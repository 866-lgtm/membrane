- In XML tool mode, a round whose tool result carries an image sends the image in a user turn of its own, and the response used to keep only the result's text, so a later request built from it showed no image and no sign of one. Now the result whose images were sent keeps what the tool returned, images included, in its block and in the response's tool results, and its block marks where the results block split (`rawXmlImagesAt`). The XML replay sends the block split there, with those images, as the turn did, so the model keeps seeing them on later turns, as in native tool mode. Later requests therefore carry those images until something removes them. A response stored before this fix replays as it did.
  - When the replay can't split a marked block (its mark no longer falls where a result closes, or no image it holds can be sent), it sends the raw text whole, and if the result still holds an image, the round report counts the message altered.
  - Results of two rounds with the same text, stored next to each other, replay as two blocks, each with its own images. They used to replay as one, and the second round's images went with its text.
- In XML tool mode, a round whose results hold images, none of which the API accepts (such as `image/bmp`), no longer splits the turn. It sent an empty user turn, which the Messages API is expected to refuse; the results now go in as text, with the note that names the refused media type where each image was.
