- Add `progressTimeoutMs` to `stream()`, `streamYielding()` and `complete()` options: a per-provider-call deadline that only progress renews (default off). Every parsed provider event renews it: an SDK event, an SSE data frame that parses, a decoded Bedrock event. SSE comments, Anthropic and Bedrock `ping`s and raw body bytes don't. So a connection that stays up while the model sends nothing still ends, which the Anthropic idle watchdog no longer bounds once keepalive bytes renew it. Each provider call gets its own deadline, refusal re-issues included, and time between calls, such as tool execution or the yielding tool wait, never counts. It bounds the wait for the first event too. A non-streaming call reports no progress before its response, so for `complete()` it bounds the whole call. On expiry the call aborts as a `TimeoutAbortError` with the message `No stream progress within <n>ms`: `stream()` returns `AbortedResponse{ reason: 'timeout' }`, `streamYielding()` emits `aborted` with reason `'timeout'`, and `complete()` throws. With the option unset, adapters receive the same options as before.
- **Provider adapters and decorators:** `ProviderRequestOptions` gains `onProgress`. A streaming adapter calls `options.onProgress?.()` once per parsed provider event, never for keepalives, comments or raw bytes; the built-in adapters and `MockAdapter` do. A decorator must forward it with the other options. An adapter or decorator that never calls it turns `progressTimeoutMs` into a total deadline for its calls. The deadline aborts the call's signal with the same mark as `timeoutMs`, so an adapter that maps `isDeadlineAbort` to `deadlineTimeoutError` needs no new error path. The Anthropic adapter now does that mapping for its caller's signal on both `stream()` and `complete()`.
