- Add `progressTimeoutMs` to `stream()`, `streamYielding()` and `complete()` options: a per-provider-call deadline that only progress renews (default off; a value that isn't a positive number of milliseconds leaves it off too). Every parsed provider event renews it: an SDK event, an SSE data frame that parses to a JSON object, a Bedrock event that decodes to one. SSE comments, Anthropic and Bedrock `ping`s and raw body bytes don't. So a connection that stays up while the model sends nothing still ends, on every adapter, at a deadline the caller sets per call. Each provider call gets its own deadline, refusal re-issues included, and time between calls, such as tool execution or the yielding tool wait, never counts. It bounds the wait for the first event too, and silence is measured on the monotonic clock, so a step of the system clock moves no expiry. A stretch with no parsed event counts as no progress whatever the model is doing: reasoning a provider doesn't stream, while it sends only keepalives, can expire the deadline, so set it above the longest such stretch you expect. Anthropic models whose thinking streams with `display: "omitted"` send no deltas while they think, which can last minutes. A call that streams no events reports no progress before its response, so the deadline bounds it as a whole: `complete()` on most adapters, and `OpenAIResponsesAdapter` (the Images API) even from `stream()`. `OpenAIResponsesAPIAdapter` in subscription mode answers `complete()` by streaming, so there its events renew the deadline. On expiry the call aborts as a `TimeoutAbortError`: `stream()` returns `AbortedResponse{ reason: 'timeout' }`, `streamYielding()` emits `aborted` with reason `'timeout'`, and `complete()` throws. Its message names the deadline and says when the call began, how many provider events it had and when the last came, for example `No provider progress within 1800000ms: the call began at 2026-10-14T12:00:00.000Z, provider events: 412, the last at 2026-10-14T12:04:10.250Z`. With the option unset, adapters receive the same options as before.
- **Provider adapters and decorators:** `ProviderRequestOptions` gains `onProgress`. A streaming adapter calls `options.onProgress?.()` once per parsed provider event, never for keepalives, comments or raw bytes; the built-in streaming adapters and `MockAdapter` do. A decorator must forward `onProgress` with the other options. An adapter or decorator that never calls it turns `progressTimeoutMs` into a total deadline for its calls. The deadline aborts the call's signal with the same mark as `timeoutMs`, so an adapter that maps `isDeadlineAbort` to `deadlineTimeoutError` needs no new error path. The Anthropic adapter now does that mapping for its caller's signal on both `stream()` and `complete()`.
